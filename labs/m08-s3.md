# Module 8 lab: Invoice bucket, versions, and a role policy

**Time:** 35 minutes  
**Region:** ap-south-1 only  
**You will create:** `sample-orders-invoices-ACCOUNTID`  
**You will not create:** a replication rule, a second bucket, or a KMS customer-managed key

## 1. Create the bucket

1. Set the region to **ap-south-1**. Copy the 12-digit account id.
2. Create a bucket named `sample-orders-invoices-` plus that account id.
3. Block all public access: **on**.
4. Versioning: **on**.
5. Default encryption: **SSE-S3** (Amazon S3 managed keys).
6. Create the bucket.

## 2. Write two versions

1. Create a text file named `invoice.txt` containing the line `version one`. Upload it to the bucket.
2. Change the file to `version two` and upload it again to the same key.
3. Open the object’s **Versions** list. Confirm two version ids and that the current version is `version two`.
4. Download the older version and confirm the body is `version one`.

## 3. Add a lifecycle rule

1. Create a lifecycle rule named `expire-noncurrent-invoices`.
2. Expire **noncurrent versions** after **30** days.
3. Do not add a transition to another storage class.

## 4. Allow the application role

1. If the role `sample-create-order-role` does not exist, create it. Trusted entity: Lambda. Permissions: basic Lambda execution only. Do not attach a policy that grants all S3 actions.
2. On the bucket, add this bucket policy. Replace both copies of `ACCOUNTID`.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCreateOrderRole",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::ACCOUNTID:role/sample-create-order-role"
      },
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::sample-orders-invoices-ACCOUNTID/*"
    }
  ]
}
```

3. Leave Block Public Access on. Do not add an explicit deny.

## 5. Write two sentences

1. What is the RPO of “we uploaded the wrong invoice,” given that version one is still in the bucket?
2. What would cross-region replication add that versioning in Mumbai does not? You are not creating it.

## 6. Cleanup

1. Empty the bucket, including **all versions and delete markers**.
2. Delete the bucket.
3. Delete `sample-create-order-role` if this lab created it.
4. Confirm the region selector never created a bucket in Singapore.

## Done when

- You downloaded `version one` after `version two` was current.
- The bucket policy names the role, and public access is still blocked.
- The bucket and its versions are gone.
